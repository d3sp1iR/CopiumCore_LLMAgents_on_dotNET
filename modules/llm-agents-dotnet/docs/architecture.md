# Архитектура модуля

Статус: начальный каркас, E0. Основание: разделы 3–5 и 18 ТЗ.

## Границы

- **Domain** — предметные типы и инварианты, без зависимостей от транспорта и SDK.
- **Application** — сценарии и порты к модели, метаграфу, памяти, записи и внешним сервисам; зависит от Domain.
- **Infrastructure** — реализации портов, клиенты и служебное хранилище; зависит от Application.
- **Api** — HTTP-хост и будущий фоновый исполнитель; точка сборки зависимостей Application и Infrastructure.
- **Console** — независимый HTTP-клиент API для демонстрационного сценария.
- **AgentRuntime** — локальный экспериментальный MAF/MEAI runtime и инструмент чтения графа.
- **TestGraphApi** — отдельный сервис синтетических объектов без ACL, предназначенный для изолированного стенда.

Ссылки между проектами зафиксированы в файлах `.csproj`. Типы и интерфейсы будут добавляться по мере появления проверяемых сценариев, чтобы не закреплять неподтверждённые контракты.

## Направление разработки

1. Зафиксировать локальные контракты и примеры ошибок; подготовить тестовый Graph API и fixture.
2. Реализовать вертикальный срез из раздела 18 ТЗ: каталог, сессия, запуск и получение результата; MAF через `IChatClient` и `getObject`.
3. Добавить долговременное хранение, авторизацию, инструменты, ревью и условную запись, затем события и восстановление.
4. После E2 реализовать индекс оснований и провести AT-17.

Служебная SQLite, outbox, интегрированная авторизация и условная запись пока не реализованы. Локальный MAF runtime и API используют демонстрационный профиль в памяти; `/ready` возвращает 503 для production-зависимостей. Наличие каркаса и unit-тестов не подтверждает выполнение приёмочных испытаний.
